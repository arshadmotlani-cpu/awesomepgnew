### SaaS migration sizing implications

- **Backfill scope:** ~3k customers, ~2k appointments, ~2k invoices — moderate; single transaction bootstrap risky; use batched backfill with checksums (see [PHASE_0B_BOOTSTRAP_MIGRATION.md](./PHASE_0B_BOOTSTRAP_MIGRATION.md)).
- **Index pressure:** Adding `(organization_id)` and `(organization_id, location_id)` indexes on high-volume tables (`fyh_invoices`, `fyh_financial_ledger`, `fyh_customer_timeline`) — plan concurrent index creation for production.
- **Unique constraints to replace:** `fyh_invoices.invoice_number` global unique → per-org composite (see JSON `uniqueConstraints`).
